# 단방향 연관관계
## 객체 관계 매핑
JPA는 외래 키 연관관계를 매핑하는 기능을 애노테이션을 통해 제공한다.

- `@ManyToOne`: 다대일 관계라는 매핑 정보다. 
- `@JoinColumn`: 외래 키를 매핑할 때 사용한다. `name` 속성에는 매핑할 외래 키 컬럼명을 지정한다.

# 연관관계의 주인
다대일 관계를 갖는 두 엔티티가 있을 때, 다대일 중 일에 해당하는 엔티티에도 연관 엔티티의 참조를 갖게 하려면 `@OneToMany` 애노테이션을 사용한다. 이때 `mappedBy` 속성에 `@ManyToOne` 애노테이션을 사용한 필드명을 지정한다. 

그런데 이 `mappedBy` 속성은 왜 필요한걸까? 엄밀히 말하면 객체에는 양방향 연관관계라는 게 없다. 그저 서로 다른 단방향 연관관계2개를 애플리케이션 로직으로 잘 묶어서 양방향인 것 처럼 보이게 할 뿐이다. 하지만 여기서 관계형 데이터베이스와 객체 지향 모델링의 패러다임 불일치가 발생한다. 테이블은 외래 키 하나로 두 테이블의 연관관계를 관리하지만, 객체가 각각 서로를 참조할 수 있게 만드려면 양방향으로 매핑해야 하고 이는 연관관계 관리 포인트가 두 개가 되버린다.

엔티티를 양방향 연관관계로 설정하면 객체의 참조는 둘인데 외래 키는 하나다. 그렇다면 둘 중 어떤 관계를 사용해서 외래 키를 관리해야 할까? 이걸 정하기 위해서 개발자는 두 객체 중 하나를 정해 테이블의 외래 키를 갖는 엔티티로 정해야 한다. 이것을 **연관관계의 주인**(Owner)이라고 한다.

이 연관관계의 주인을 `mappedBy` 속성으로 지정한다. 여기에는 다음과 같은 규칙이 있다.

- 주인은 `mappedBy` 속성을 사용하지 않는다.
- 주인이 아니면 `mappedBy` 속성을 사용해서 속성의 값으로 연관관계의 주인을 지정해야 한다.
