# 프록시
## 프록시 기초
JPA에서 식별자로 엔티티 하나를 조회할 땐 `EntityManager.find()`를 사용한다. 이 메소드는 영속성 컨텍스트에 엔티티가 없으면 데이터베이스를 조회한다.
```java
Jewoo jewoo = em.find(Jewoo.class, 1L);
```
이 방법은 조회한 엔티티를 실제로 사용하든 하지 않든 데이터베이스를 조회한다. 이 조회 작업을 엔티티를 실제로 사용하는 시점까지 미루고싶으면 `EntityManager.getReference()`를 사용하면 된다. 이 메소드는 데이터베이스를 조회하지도, 실제 엔티티 객체를 생성하지도 않는다. 대신 데이터베이스 접근을 위임한 프록시 객체를 반환한다. 

### 프록시의 특징
프록시 클래스는 실제 클래스를 상속받아서 만들어진다. 따라서 실제 클래스와 겉 모양이 같다. 사용자는 이게 진짜 객체인지 프록시 객체인지 구분하지 않고 사용하면 된다.

프록시 객체는 실제 객체에 대한 참조(target)를 가지고 있다. 사용자가 프록시 객체의 메소드를 호출하면 프록시 객체는 실제 객체의 메소드를 호출한다.

프록시의 특징은 다음과 같다.

- 프록시 객체는 처음 사용할 때 한 번만 초기화된다.
- 프록시 객체를 초기화한다고 프록시 객체가 실제 엔티티로 바뀌는 건 아니다. 초기화되면 프록시 객체를 통해서 실제 엔티티에 접근할 수 있다.
- 프록시 객체는 원본 엔티티를 상속받은 객체이므로 타입 체크 시 주의해서 사용해야 한다.
- 영속성 컨텍스트에 찾는 엔티티가 이미 있으면 데이터베이스를 조회할 필요가 없으므로 `em.getReference()`를 호출해도 프록시가 아닌 실제 엔티티를 반환한다.
- 초기화는 영속성 컨텍스트의 도움을 받아야 가능하다. 따라서 준영속 상태의 프록시를 초기화하면 문제가 발생한다. 

## 프록시와 식별자
엔티티를 프록시로 조회할 때 식별자(PK) 값을 파라미터로 전달하는데, 프록시 객체는 이 식별자 값을 보관한다. 그래서 프록시 객체로 식별자 값을 조회하는 `getId()` 같은 메서드를 호출해도 프록시를 초기화하지 않는다. 단 엔티티 접근 방식을 프로퍼티(`@Access(AccessType.PROPERTY)`)로 설정한 경우에 한해서다. 엔티티 접근 방식을 필드로 설정하면 JPA는 `getId()` 메소드가 id만을 조회하는 메소드인지 다른 필드까지 활용해서 어떤 일을 하는 메소드인지 알지 못해 프록시 객체를 초기화한다.

하지만 연관관계를 설정할 땐 엔티티 접근 방식이 무엇이든 상관없이 프록시를 초기화하지 않는다. 연관관계를 설정하는 과정에서는 식별자 값만 사용하는 것이 확실하기 때문이다. 따라서 프록시는 연관관계를 설정할 때 유용하며, 프록시를 사용해 연관관계를 설정하면 데이터베이스 접근 횟수를 줄이는 효과를 볼 수 있다.
