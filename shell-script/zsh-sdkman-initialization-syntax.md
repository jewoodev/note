# zsh의 SDKMAN 초기화 코드 읽기

SDKMAN은 Java 등의 개발 도구를 설치하고 사용할 버전을 선택하는 도구다. 설치된 SDKMAN을 현재 터미널에서 사용하려면 초기화 스크립트를 셸에 불러와야 한다.

다음은 zsh에서 사용하는 초기화 코드다.

```sh
export SDKMAN_DIR="$HOME/.sdkman"
[[ -s "$SDKMAN_DIR/bin/sdkman-init.sh" ]] &&
  source "$SDKMAN_DIR/bin/sdkman-init.sh"
```

전체 의미는 다음과 같다.

> SDKMAN 설치 경로를 설정하고, 초기화 파일이 존재하며 비어 있지 않으면 현재 셸에서 그 파일의 명령을 실행한다.

## 1. 변수에 값을 저장하고 환경변수로 내보내기

```sh
export SDKMAN_DIR="$HOME/.sdkman"
```

| 문법 | 의미 |
| --- | --- |
| `SDKMAN_DIR=값` | 변수에 값을 저장한다. `=` 양옆에는 공백을 넣지 않는다. |
| `$HOME` | 현재 사용자의 홈 디렉토리 값으로 치환된다. |
| `"..."` | 경로에 공백이나 특수문자가 있어도 하나의 값으로 다루도록 인용한다. 변수 치환은 허용한다. |
| `export` | 변수를 현재 셸의 환경변수로 만들어 이후 실행하는 자식 프로세스에도 전달한다. |

예를 들어 `HOME`이 `/Users/example`이라면 저장되는 값은 다음과 같다.

```text
/Users/example/.sdkman
```

큰따옴표 자체가 값에 포함되는 것은 아니다. 작은따옴표를 사용하면 변수 치환이 일어나지 않는다는 차이가 있다.

```sh
SDKMAN_DIR="$HOME/.sdkman"  # 홈 디렉토리 경로로 치환
SDKMAN_DIR='$HOME/.sdkman'  # $HOME이라는 글자를 그대로 저장
```

일반 변수도 현재 셸에서는 사용할 수 있다. `export`는 그 값을 자식 프로세스에도 전달한다는 의미이며, 다른 터미널이나 이미 실행 중인 프로세스의 환경을 바꾸지는 않는다.

## 2. 초기화 파일을 검사하기

```sh
[[ -s "$SDKMAN_DIR/bin/sdkman-init.sh" ]]
```

`[[ ... ]]`는 zsh의 조건 검사 구문이다. `[[`와 `]]` 안쪽에는 공백을 둔다.

`-s 파일경로`는 파일이 존재하고 크기가 0보다 크면 참으로 판단한다. 위 코드는 SDKMAN 초기화 파일이 존재하고 비어 있지 않은지 확인한다.

이는 파일을 읽을 권한이나 스크립트 내용의 유효성까지 보장하는 검사는 아니다. 조건이 참이어도 이후 `source` 실행은 실패할 수 있다.

## 3. 조건이 참일 때만 다음 명령 실행하기

```sh
앞의_명령 && 뒤의_명령
```

`&&`는 앞 명령의 종료 상태가 `0`, 즉 성공일 때만 뒤 명령을 실행한다. 조건 검사도 참이면 종료 상태 `0`, 거짓이면 0이 아닌 값을 반환하므로 이 구조에 사용할 수 있다.

초기화 코드에서는 파일 검사가 참일 때만 `source`를 실행한다.

```sh
[[ -s "$SDKMAN_DIR/bin/sdkman-init.sh" ]] &&
  source "$SDKMAN_DIR/bin/sdkman-init.sh"
```

`&&` 뒤에는 다음 명령이 필요하므로 줄을 바꿔도 구문이 이어진다. 이 위치에서는 줄 연결 문자 `\`를 붙이지 않아도 된다. 두 번째 줄의 들여쓰기는 가독성을 위한 것이다.

실행 조건을 `if`로 풀어 쓰면 다음과 같다.

```sh
if [[ -s "$SDKMAN_DIR/bin/sdkman-init.sh" ]]; then
  source "$SDKMAN_DIR/bin/sdkman-init.sh"
fi
```

여기서 `;`는 같은 줄에서 조건 검사 명령을 끝내는 구분자다. `then` 다음부터 `fi` 전까지가 조건이 참일 때 실행할 부분이다. 두 표현은 본문 실행 조건이 같지만, 조건이 거짓일 때 전체 구문의 종료 상태까지 같다는 뜻은 아니다.

## 4. 현재 셸에서 스크립트 불러오기

```sh
source "$SDKMAN_DIR/bin/sdkman-init.sh"
```

`source`는 파일에 적힌 명령을 현재 셸에서 실행한다. 따라서 그 파일이 정의한 함수와 환경 설정을 이후 같은 셸에서 사용할 수 있다. SDKMAN의 `sdk` 명령도 이러한 초기화 과정을 통해 사용할 수 있게 된다.

별도의 셸 프로세스로 스크립트를 실행하면 그 안에서 변경한 환경이 부모 셸에 반영되지 않는다. 현재 터미널의 환경을 설정하려는 목적에는 `source`가 필요하다.

zsh에서는 다음처럼 `.`으로도 표현할 수 있다.

```sh
. "$SDKMAN_DIR/bin/sdkman-init.sh"
```

`source`는 파일 내용을 현재 셸에서 실행하므로 읽을 수 있는 파일이어야 한다. 파일 자체에 실행 권한을 부여할 필요는 없다.

## 5. 설정 파일마다 맡는 역할

| 파일 | 역할 |
| --- | --- |
| `~/.zshrc` | 대화형 zsh 시작 시 SDKMAN 초기화 코드를 실행한다. |
| `~/.sdkman/etc/config` | `sdkman_auto_env=true` 같은 SDKMAN 동작 옵션을 설정한다. |
| 프로젝트의 `.sdkmanrc` | `java=17.0.19-amzn`처럼 해당 프로젝트에서 사용할 버전을 지정한다. |

`.sdkmanrc`를 만드는 것만으로 셸이 SDKMAN을 초기화하지는 않는다. SDKMAN이 초기화된 상태에서 `sdk env`를 실행하거나 자동 전환 기능을 사용해야 해당 설정이 적용된다.

비대화형 zsh는 일반적으로 `.zshrc`를 읽지 않는다. 자동화 명령에서는 필요한 초기화와 프로젝트 환경 적용을 명시적으로 수행할 수 있다.

```sh
source "$HOME/.sdkman/bin/sdkman-init.sh"
cd /path/to/project
sdk env
```

위 예시는 SDKMAN과 프로젝트가 지정한 JDK가 이미 설치되어 있다고 가정한다.
