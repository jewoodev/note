# `uv run python /dev/stdin <<'PY'` 호출 방식 정리

`uv run python /dev/stdin <<'PY' ... PY`는 표준입력으로 파이썬 스크립트를 전달해서 실행하는 방식이다.

예시:

```bash
uv run python /dev/stdin <<'PY'
from pathlib import Path
Path("example.txt").write_text("hello\n")
PY
```

## 구성 요소

### `uv run python`

프로젝트의 uv 환경에서 Python을 실행한다. 이 저장소 규칙상 시스템 Python을 직접 호출하지 않고 uv를 통해 실행하기 위해 사용한다.

### `/dev/stdin`

Python에게 스크립트 파일을 표준입력에서 읽으라고 알려주는 특수 파일 경로다. 실제 `.py` 파일을 만들지 않아도 여러 줄짜리 Python 코드를 실행할 수 있다.

### `<<'PY' ... PY`

shell의 here-document 문법이다. 종료 마커인 `PY`가 나올 때까지의 내용을 명령의 stdin으로 전달한다.

작은따옴표가 붙은 `<<'PY'`는 shell 변수 치환, 명령 치환, 백슬래시 해석 같은 확장을 하지 말라는 뜻이다. 그래서 Python 코드가 shell에 의해 변형되지 않고 그대로 전달된다.

## 왜 이 방식을 쓰는가

이 프로젝트의 작업 규칙은 파일 생성, 수정, 삭제를 직접 편집 도구로 하지 않고 `uv run python <script>`로 실행되는 스크립트 안에서 처리하도록 요구한다.

짧은 일회성 파일 작업에서는 별도 임시 `.py` 파일을 만들 필요가 없으므로 `/dev/stdin`으로 스크립트를 전달하는 방식이 가볍다.

## 장점

- 시스템 Python을 직접 호출하지 않고 uv 환경을 사용한다.
- 임시 Python 파일을 만들지 않아도 된다.
- 여러 줄짜리 스크립트를 한 번에 실행할 수 있다.
- `<<'PY'`를 사용하면 shell 확장으로 인한 의도치 않은 변형을 줄일 수 있다.

## 주의할 점

- 이 방식은 shell here-document라서 명령 기록이나 실행 로그에 스크립트 내용이 남을 수 있다.
- 길거나 재실행, 디버깅, 리뷰 가치가 있는 스크립트는 별도 `.py` 파일로 두는 편이 낫다.
- 여기서 `PY`는 관례적인 종료 마커일 뿐이며, `EOF` 같은 다른 문자열도 사용할 수 있다. 시작 마커와 종료 마커가 정확히 일치하면 된다.
- 문서나 스크립트 내용 안에 종료 마커와 같은 단독 줄이 들어가면 here-document가 예상보다 빨리 끝난다. 그럴 때는 `CODEX_PY`처럼 충돌하지 않는 마커를 사용하면 된다.
