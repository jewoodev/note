# Kotlin의 `@Synchronized`와 JVM 모니터 잠금

이 문서는 Kotlin/JVM에서 여러 스레드가 같은 객체의 상태를 안전하게 다룰 때 사용하는 `@Synchronized`와 모니터 잠금을 설명한다.

## 여러 스레드가 상태를 공유할 때

두 스레드가 같은 잔액을 동시에 읽고 변경한다고 생각해 보자. 잔액이 100일 때 각 스레드가 10을 더한다면 기대 결과는 120이다. 하지만 둘 다 변경 전 값인 100을 읽고 각각 110을 저장하면 최종 결과는 110이 될 수 있다. 읽기와 계산, 쓰기가 하나의 분리할 수 없는 작업으로 실행되는 것은 아니기 때문이다.

이때 관련 작업을 **같은 잠금으로 보호**하면 한 스레드가 상태를 읽고 바꾸는 동안 다른 스레드는 잠금이 풀릴 때까지 기다린다.

## 모니터 잠금이란?

JVM에서 객체마다 사용할 수 있는 잠금을 *모니터 잠금*이라고 한다. 스레드가 어떤 객체의 모니터 잠금을 얻으면, 다른 스레드는 같은 잠금을 얻을 때까지 기다려야 한다. 잠금을 가진 스레드가 보호된 영역을 벗어나 잠금을 해제하면 기다리던 스레드 중 하나가 실행을 이어갈 수 있다. 실행 순서나 대기 시간은 보장되지 않는다.

잠금은 **어떤 객체를 잠금으로 사용하느냐**에 따라 구분된다. 서로 다른 객체의 모니터 잠금은 서로 독립적이다.

## 인스턴스 메서드의 `@Synchronized`

Kotlin/JVM에서 인스턴스 메서드에 `@Synchronized`를 붙이면, 메서드를 실행할 때 **그 메서드를 호출한 인스턴스의 모니터 잠금**을 사용한다.

```kotlin
class Counter {
    private var value = 0

    @Synchronized
    fun increment() {
        value += 1
    }

    @Synchronized
    fun current(): Int = value
}
```

예를 들어 두 스레드가 같은 `counter` 객체의 `increment()`와 `current()`를 호출하면, 둘 다 `counter`의 모니터 잠금을 얻어야 한다. 한 스레드가 잠금을 가진 동안 다른 스레드는 메서드 본문에 들어가기 전에 기다린다.

반면 `Counter()`로 만든 서로 다른 두 객체의 메서드는 각자 다른 잠금을 사용한다. 한 객체에서 `increment()`가 실행 중이어도 다른 객체의 `increment()`는 실행될 수 있다.

## 객체 전체가 자동으로 막히는 것은 아니다

잠금이 객체에 연결되어 있다는 말은 객체의 모든 메서드나 속성 접근이 자동으로 차단된다는 뜻이 아니다. **같은 모니터 잠금을 사용하는 코드끼리만** 서로 기다린다.

위 예제에서 `value`를 잠금 없이 읽거나 변경하는 다른 메서드를 추가한다면, 그 메서드는 `@Synchronized` 메서드가 실행 중이어도 동시 실행될 수 있다. 공유 상태를 안전하게 다루려면 그 상태에 접근하는 모든 경로가 같은 동기화 규칙을 따라야 한다.

`@Synchronized`는 메서드 전체를 잠금으로 보호한다. 특정 코드 구간만 보호하려면 다음처럼 잠금으로 사용할 객체를 명시할 수 있다.

```kotlin
class Counter {
    private val lock = Any()
    private var value = 0

    fun increment() {
        synchronized(lock) {
            value += 1
        }
    }

    fun current(): Int = synchronized(lock) { value }
}
```

여기서는 `Counter` 인스턴스가 아니라 `lock` 객체의 모니터를 사용한다. 따라서 두 메서드를 함께 보호하려면 둘 다 **같은 `lock` 인스턴스**를 사용해야 한다. `@Synchronized` 인스턴스 메서드와 `synchronized(lock)`은 서로 다른 잠금을 쓰므로 자동으로 조율되지 않는다.

## 잠금의 수명과 성질

- 메서드나 `synchronized` 블록에 들어가기 전에 잠금을 얻고, 정상 반환하거나 예외로 빠져나갈 때 해제한다.
- 모니터 잠금은 **재진입 가능**하다. 이미 잠금을 가진 스레드는 같은 잠금을 다시 얻을 수 있다. 예를 들어 동기화된 메서드가 같은 객체의 다른 동기화된 메서드를 호출할 수 있다.
- 같은 잠금을 통한 해제와 이후 획득은 메모리 가시성도 제공한다. 잠금을 해제하기 전에 수행한 변경은 이후 같은 잠금을 얻은 스레드에 보인다. 잠금 없이 접근하는 경로까지 이 규칙이 자동으로 적용되는 것은 아니다.
- 잠금은 JVM의 스레드 사이를 조율한다. 다른 프로세스나 다른 기기의 코드까지 자동으로 조율하지 않는다.

## 사용할 때 주의할 점

잠금 안에서 네트워크 호출이나 오래 걸리는 작업을 수행하면 같은 잠금을 원하는 다른 스레드가 그동안 기다린다. 반대로 잠금 밖으로 필요한 작업을 옮기면 그 사이에 상태가 바뀔 수 있으므로, 어떤 작업을 하나의 단위로 보호해야 하는지 먼저 정해야 한다.

또한 여러 잠금을 서로 다른 순서로 획득하면 각 스레드가 상대방의 잠금을 기다리는 **교착 상태**가 발생할 수 있다. 필요한 잠금을 가능한 한 적게 사용하고, 여러 잠금이 필요하다면 획득 순서를 일관되게 정한다.

`@Synchronized`는 Kotlin/JVM의 스레드와 모니터를 위한 기능이다. 코루틴의 일시 중단을 고려한 잠금이 필요한 경우에는 코루틴용 동기화 도구를 검토해야 한다.
