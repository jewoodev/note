# 로그인 셸과 대화형 셸 이해하기

셸은 명령을 해석하고 프로그램을 실행하는 프로그램이다. 터미널 앱은 셸과 상호작용하는 창을 제공한다. 터미널 앱, 셸, 운영체제 로그인은 서로 다른 개념이다.

**로그인 여부와 대화형 여부는 독립적인 두 축이다.** 따라서 셸은 네 가지 조합으로 실행될 수 있다. 아래 초기화 파일과 명령 예시는 macOS에서 흔히 사용하는 **zsh의 기본 모드**를 기준으로 한다. Bash 등 다른 셸에 파일 이름과 읽기 규칙을 그대로 적용하면 안 된다.

## 두 가지 구분 기준

### 로그인 셸과 비로그인 셸

로그인 셸은 로그인 환경을 초기화하도록 시작한 셸이다. 이름 때문에 사용자 인증이나 비밀번호 입력을 반드시 동반한다고 생각하기 쉽지만, 이미 열린 터미널에서도 `zsh -l`로 실행할 수 있다.

비로그인 셸은 로그인 모드 없이 시작한 셸이다. 기존 셸에서 새 셸을 실행할 때 흔히 사용하며, 부모 프로세스가 전달한 환경을 이어받을 수 있다.

로그인 셸 여부는 시작 방식에 달려 있다. 터미널 창이나 탭을 새로 열었다는 사실만으로 단정할 수 없으며 터미널 앱의 설정을 확인해야 한다.

### 대화형 셸과 비대화형 셸

대화형 셸은 사용자가 명령을 입력하며 작업하는 모드다. 프롬프트, 명령 기록, 자동 완성, 키 바인딩 같은 기능이 이 환경에 해당한다.

비대화형 셸은 스크립트나 전달받은 명령을 실행하는 데 사용한다. 배치 작업, CI, 자동화 도구에서 흔하다. 터미널 창에서 실행한 명령이라도 그 명령이 시작한 자식 셸은 비대화형일 수 있다.

zsh의 `-i`는 대화형 모드를 강제하며, `-c`는 뒤의 문자열을 명령으로 실행한다. 두 옵션은 함께 사용할 수도 있다. [zsh 공식 문서: Invocation](https://zsh.sourceforge.io/Doc/Release/Invocation.html)

## 네 가지 조합

| 로그인 여부 | 대화형 여부 | 명시적 실행 예 | 사용 상황 |
| --- | --- | --- | --- |
| 로그인 | 대화형 | `zsh -li` | 로그인 환경과 사용자 작업 환경을 함께 초기화 |
| 비로그인 | 대화형 | `zsh -i` | 기존 환경에서 대화형 셸을 추가 실행 |
| 로그인 | 비대화형 | `zsh -lc 'command -v uv'` | 로그인 초기화 후 지정 명령 실행 |
| 비로그인 | 비대화형 | `zsh -c 'command -v uv'` | 상속받은 환경에서 지정 명령 실행 |

`zsh -lc`에는 로그인 옵션이 있지만 대화형 옵션은 없다. 따라서 로그인 설정은 읽어도 대화형 설정은 읽지 않는다.

## zsh 초기화 파일의 읽기 순서

기본 설정에서 사용자 파일은 다음 순서로 읽힌다. 각 파일이 존재하는 경우에 해당한다.

```text
모든 모드       ~/.zshenv
    ↓
로그인인 경우   ~/.zprofile
    ↓
대화형인 경우   ~/.zshrc
    ↓
로그인인 경우   ~/.zlogin
```

| 사용자 파일 | 로그인·대화형 | 비로그인·대화형 | 로그인·비대화형 | 비로그인·비대화형 |
| --- | --- | --- | --- | --- |
| `.zshenv` | 읽음 | 읽음 | 읽음 | 읽음 |
| `.zprofile` | 읽음 | — | 읽음 | — |
| `.zshrc` | 읽음 | 읽음 | — | — |
| `.zlogin` | 읽음 | — | 읽음 | — |

각 단계에서는 시스템 파일이 사용자 파일보다 먼저 읽힌다. 예를 들어 `/etc/zprofile` 다음에 사용자 `.zprofile`이 온다. 사용자 파일의 기본 위치는 홈 디렉터리이며 `ZDOTDIR`를 설정하면 달라진다. 시스템 파일 위치도 설치에 따라 다를 수 있다. `RCS`, `GLOBAL_RCS` 옵션이나 `-f` 등으로 기본 읽기 동작을 바꿀 수 있다. [zsh 공식 문서: Startup/Shutdown Files](https://zsh.sourceforge.io/Doc/Release/Files.html#Startup_002fShutdown-Files)

일반적인 설정 배치는 다음과 같다.

- `.zshenv`: 모든 zsh 실행에 필요한 최소 설정. 출력이나 무거운 초기화는 피한다.
- `.zprofile`: 로그인 시 적용할 환경 설정.
- `.zshrc`: 프롬프트, 자동 완성, 별칭 등 대화형 작업 설정.
- `.zlogin`: 로그인 초기화의 마지막 단계에 필요한 작업. 별도 필요가 없다면 사용하지 않아도 된다.

기본 모드의 zsh가 `~/.profile`을 자동으로 읽는다고 가정하면 안 된다. 설정을 공유하려면 명시적으로 불러오거나 사용하는 셸의 초기화 파일에 배치한다.

## 같은 명령인데 PATH가 다른 이유

`PATH`는 실행 파일을 찾을 디렉터리 목록이다. 예를 들어 `uv`를 실행하면 셸은 명령 해석 과정에서 PATH의 디렉터리들을 검색한다. 실행 파일이 설치돼 있어도 그 위치가 PATH에 없으면 찾지 못할 수 있다.

다음 설정이 `.zshrc`에만 있다고 가정하자.

```sh
export PATH="$HOME/.local/bin:$PATH"
```

대화형 셸에서는 이 설정을 읽으므로 `~/.local/bin/uv`를 찾을 수 있다. 반면 비대화형 로그인 셸은 `.zshrc`를 읽지 않으므로 이 줄을 적용하지 않는다.

다만 **초기화 파일을 읽지 않았다는 사실이 해당 경로가 반드시 없다는 뜻은 아니다.** 자식 프로세스는 부모가 내보낸 환경 변수를 상속받는다. 부모의 PATH에 이미 그 경로가 있다면 비대화형 셸에서도 명령을 찾을 수 있다.

그래서 터미널, IDE, 자동화 실행기에서 결과가 달라질 수 있다. 확인할 대상은 다음 세 가지다.

1. 부모 프로세스가 전달한 PATH.
2. 실제 셸의 로그인·대화형 모드와 읽은 초기화 파일.
3. 실행기가 주입한 환경 변수 또는 저장해 둔 환경 스냅샷.

작업 디렉터리 변경 자체가 zsh의 로그인 여부를 바꾸지는 않는다. 디렉터리를 달리 지정했을 때 결과가 달라진다면 실행기나 디렉터리별 환경 도구의 동작도 확인해야 한다.

## PATH 설정 중복 피하기

같은 경로 추가문을 `.zprofile`과 `.zshrc`에 모두 넣으면 로그인·대화형 셸에서는 두 번 실행된다. 같은 경로가 중복돼도 명령을 찾는 데 보통 문제는 없지만, 반복 초기화로 PATH가 길어질 수 있다.

필요한 초기화 파일에서 다음처럼 존재 여부를 확인하면 중복 추가를 피할 수 있다.

```sh
case ":$PATH:" in
  *":$HOME/.local/bin:"*) ;;
  *) export PATH="$HOME/.local/bin:$PATH" ;;
esac
```

앞뒤의 콜론은 디렉터리 항목의 경계를 구분하기 위한 것이다. 이 코드는 기존 중복을 제거하거나 이미 있는 경로의 우선순위를 바꾸지는 않는다.

설정 위치는 필요한 범위에 맞춘다. 로그인 셸에는 `.zprofile`, 대화형 셸에는 `.zshrc`를 사용할 수 있다. 두 모드 모두 필요하면 위 코드를 두 파일에서 사용하거나 작은 공통 설정 파일을 불러올 수 있다. 비로그인·비대화형 실행까지 필요하면 `.zshenv` 또는 실행기 자체의 환경 설정을 검토한다.

자동화 명령 하나에만 적용하려면 다음처럼 환경을 명시할 수도 있다. 영구 설정 파일은 바뀌지 않는다.

```sh
PATH="$HOME/.local/bin:$PATH" uv --version
```

## 현재 환경 확인하기

아래 명령은 zsh 안에서 실행한다.

```zsh
# 실제 셸 모드
print -r -- "login=$options[login] interactive=$options[interactive]"

# 명령 검색 결과
command -v uv

# PATH를 디렉터리별로 출력
print -l -- $path
```

`$SHELL`은 현재 프로세스의 로그인·대화형 여부를 판별하는 값이 아니다. 실행 도구에 지정한 옵션만 믿기보다 실제 셸 상태와 PATH를 함께 확인하는 편이 정확하다.

초기화 파일을 수정해도 이미 실행 중인 다른 프로세스의 환경은 자동으로 바뀌지 않는다. 새 셸을 실행하거나 필요한 설정을 현재 셸에 적용해야 한다. IDE나 자동화 실행기가 기존 환경을 보관하고 있다면 그 환경도 별도로 갱신해야 한다.

명령 검색과 파일 접근 권한은 별개다. PATH를 수정해 실행 파일을 찾게 됐더라도 캐시 디렉터리 등에 대한 권한이나 샌드박스 제한으로 프로그램 실행이 실패할 수 있다.
