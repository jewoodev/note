# 채팅방 이름이 달라도 같은 방일 수 있다

실기기에서 카카오톡 단체방을 정확히 열었는데, 화면 제목을 등록한 이름과 대조하니 일치하지 않았다. 예상한 방 이름 뒤에 카카오톡이 참여자 수를 붙여 표시했기 때문이다. 기존 전송 프로그램처럼 제목의 모든 글자가 같아야 통과하는 검사에서는 올바른 방도 걸러진다. 제목 검사를 느슨하게 하면 이름이 비슷하거나 같은 두 방을 어떻게 구분할까?

이 문제는 내부 업무 시스템인 ERP에서 예약한 공지를 별도 서비스인 비서가 여러 카카오톡 방에 보내는 기능을 만들 때 만났다. 비서는 안드로이드 기기에서 방을 열고 본문을 입력한 뒤 전송 버튼을 누른다. 사람이 화면을 계속 보고 있지 않으므로, 프로그램이 지금 열린 방의 정체를 확인할 수 있어야 했다.

## 방을 열 때 사용한 ID와 실제로 열린 방의 ID

비서는 채팅방을 등록할 때 확인한 숫자 방 ID를 보관한다. 이전 검증에서 이 값을 사용해 일반 단체방과 오픈채팅을 다시 열 수 있었다. 여기서 한 단계 더 필요한 건 **방을 열라는 요청에 넣은 값과, 요청 후 실제로 열린 화면에서 읽은 값**을 대조하는 일이다. 열기 요청이 의도한 방 ID는 프로그램이 가려고 한 곳을 알려준다. 화면에 연결된 방 ID를 읽으면 프로그램이 실제로 어디에 도착했는지 확인할 수 있다.

안드로이드에서는 화면을 담당하는 구성 요소를 Activity라고 부른다. 실기기에서 별도 검증 도구로 현재 활성 채팅 Activity에 연결된 방 ID를 읽었다. 확인 지점은 본문을 입력하기 전과 시험 본문을 입력해 전송 버튼이 활성화된 후였다. 방이 맞다는 확인을 본문 입력 전에 한 번, 전송에 가장 가까운 시점에 한 번 할 수 있는지 보고 싶었다.

| 실기기에서 확인한 상황 | 관찰 결과 |
| --- | --- |
| 등록한 일반 단체방 열기 | 두 지점에서 방 ID가 일치했다. 화면 제목에는 참여자 수가 붙어 문자열 대조는 실패했다. |
| 등록한 오픈채팅 열기 | 두 지점에서 방 ID가 일치했다. |
| 일반 단체방을 기대한 상태에서 다른 방 열기 | 실제 화면의 방 ID가 기대한 값과 다르다는 것을 감지했다. |

검증은 전송 버튼이 활성화되는 지점까지였다. 시험 본문은 지웠고 카카오톡을 발송하지 않았다. 이 기록에서 확인한 건 지정된 두 방에서 ID를 읽고, 다른 방과의 불일치를 감지할 수 있었다는 사실이다.

## 확인할 수 없는 화면에서의 동작

이 관찰을 바탕으로 새 전송 프로그램에 **본문 입력 전과 전송 버튼을 누르기 직전 모두 실제 방 ID를 확인하는 검사**를 넣었다. 제목은 채팅 화면인지 파악하는 데 보조 정보로 쓰인다. ID가 다르거나 읽을 수 없으면 그 방에 전송하지 않는다.

운영에서는 기기의 카카오톡 발신 계정을 고정한다. 계정을 바꿀 때는 일일 전송을 중지하고, 이전 계정으로 만든 예약을 새 계정에서 자동으로 이어서 보내지 않기로 했다. 별도 실기기 검증에서 방 ID는 읽을 수 있었지만, 그 도구가 카카오톡의 실제 로그인 계정까지 확인한 것은 아니었다.

제목이 실제로 변경된 방, 등록 해제 뒤에도 기기가 계속 참여 중인 방, 같은 제목의 두 방을 구분하는 동작은 새 전송 프로그램을 적용한 실기기에서 별도로 확인할 항목이다. 참여자 수가 제목에 붙은 사례와 실제 제목을 변경한 사례를 구분해서 기록해 뒀다.
